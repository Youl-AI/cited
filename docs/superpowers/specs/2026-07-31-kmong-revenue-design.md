# 크몽 수익화 단계 설계 (구 4단계 대체)

2026-07-31 승인. 이 문서가 `2026-07-28-cited-phase-4-billing-and-onboarding.md`를
**대체한다** — 토스 결제·온보딩 마법사·Trigger.dev·주간 수집은 크몽 수익이
확인된 뒤로 미룬다 (2026-07-31 결정: PG 가입비 33만원은 유료 고객 0명 상태에서
내지 않는다. 첫 고객 몇 명은 계좌이체·크몽으로 받는다).

## 목표

크몽에서 GEO 진단을 팔아 첫 유료 매출을 만든다. 세 축:

1. **결과물** — 구매자가 "돈 냈다"고 느끼는 리포트·PDF
2. **상품 설명** — 크몽 등록 문안
3. **성능** — 어떤 업종이 들어와도 측정이 무너지지 않는다

## 상품 구조

| 티어 | 구성 | 가격 |
|---|---|---:|
| 무료 샘플 | 3질의 × 1회 = 답변 6개 (기존 무료 진단, 문의 응대용) | 0원 |
| STANDARD | 10질의 × 3회 = 답변 60개 리포트 | 49,000원 |
| DELUXE ★ | + 개선 가이드 | 99,000원 |
| PREMIUM | + 4주 뒤 재측정 · 전후 비교 | 189,000원 |

- 주력은 DELUXE. 진짜 원가는 API(~2,400원)가 아니라 가이드 작성 시간(30~60분)이다.
- 오픈 할인(첫 5~10건, 예: DELUXE 69,000)을 명시하고 후기가 쌓이면 정가 복귀.
  정가를 낮게 박으면 나중에 못 올린다 — 할인은 걷으면 된다.
- 99,000원은 나중에 SaaS Starter(월 99,000)와 앵커링을 이룬다: "1회 진단
  가격으로 매주 3회 측정".
- PREMIUM 재측정은 **동결된 질의를 그대로** 재실행한다. 비교 가능성이 상품의
  근거다.
- 퍼널: 크몽 문의 → 무료 샘플 배송 → 맘에 들면 DELUXE → 상위 옵션 PREMIUM.

## 데이터 모델 — `free_audits` 확장

새 테이블을 만들지 않는다. 열 추가:

| 열 | 타입 | 뜻 |
|---|---|---|
| `tier` | `'free' \| 'standard' \| 'deluxe' \| 'premium'` | 기본 `'free'` |
| `region` | text nullable | 지역형 업종의 지역. 전국형은 null |
| `queries` | jsonb nullable | **동결된 질의 목록.** null이면 템플릿에서 생성(기존 무료 동작 그대로) |
| `guideMd` | text nullable | 운영자가 쓰는 개선 가이드(마크다운). DELUXE부터 |
| `parentId` | text nullable | PREMIUM 재측정이 원본 진단을 가리킨다 (전후 비교 연결) |

- **이 스키마가 곧 SaaS 온보딩 데이터다.** 질의·별칭·경쟁사·도메인·측정
  이력이 고객 단위로 남으므로 구독 전환 시 이 행이 첫 데이터 포인트가 된다.
- 진단 티어는 `plans.ts`의 PLANS(구독 플랜)와 **섞지 않는다.** 별도 상수
  `AUDIT_TIERS`에 질의 수·반복 수를 정의한다. PLANS는 구독의 것이다.

## 맞춤 질의 흐름 (승인된 C안)

```
크몽 주문 → audit:new --tier deluxe --region "강남" …
         → audit:queries <id>            LLM이 업종·서비스 기반 후보 7개 생성
         → 운영자가 파일로 검수·수정
         → audit:queries <id> --freeze   DB에 동결
         → audit:run <id> --dry          눈으로 확인
         → audit:run <id> --base-url https://cited.co.kr
```

- 질의 구성: **템플릿 3개(항상 포함) + 맞춤 7개.** 무료 샘플에서 봤던 질문이
  정밀에도 들어 있어 연속성이 생긴다.
- 생성은 주문당 1회, 검수 후 영구 동결. 즉석 생성 금지 — 재실행 비교
  가능성(결정성)은 **고객 단위 동결**로 지킨다.
- 검증은 코드가 강제한다: 브랜드명·경쟁사명 포함 시 거부, 지역형 업종에
  지역 누락 시 거부, 개수·중복 검사. 검수자 눈에 맡기지 않는다.

## 업종 템플릿 확장 (~25개)

- **전국형 ~10개** (지역 불필요): 기존 5(패션·화장품·식품·가전·교육) +
  이커머스 · 앱/온라인서비스 · 여행/숙박예약 · 금융/핀테크 · 프랜차이즈 등
- **지역형 ~15개** (지역 필수): 치과 · 피부과/성형 · 한의원 · 동물병원 ·
  필라테스/요가 · 헬스장 · 미용실/네일 · 학원 · 변호사 · 세무사 ·
  인테리어 · 이사/청소 · 식당/카페 · 웨딩 · 부동산 등
- 지역형 질의는 `{지역}` 슬롯을 쓴다: `"{지역} 치과 어디가 좋아?"`.
  **지역이 없으면 실행을 거부한다** — 조용히 일반형으로 강등하면 무의미한
  측정이 고객에게 배송된다.
- 지역 입력은 **CLI(`--region`)만** (2026-07-31 결정, A안). 웹 폼은 그대로
  두고, 지역 문의가 많아지면 웹 적용을 재검토한다.
- 질의 75개(25업종 × 3)는 구현 계획서에 전부 명기하고 하나씩 검수한다.
  LLM 즉석 생성 금지.
- **커버리지보다 추가 속도.** 크몽은 문의가 먼저 오므로 모르는 업종도 주문
  전에 추가할 시간이 있다. 새 업종 추가가 10분 작업이 되도록 템플릿 구조와
  검증 테스트(질의 3개·지역형 여부·별칭 겹침 자동 검사)를 갖춘다.

## 납품물 — PDF + 웹 링크 (승인된 B안)

- `audit:pdf <id>` — Playwright(설치됨)로 리포트 페이지를 인쇄 렌더 → PDF.
  크몽 메시지에 파일 첨부 + 웹 링크 병기. 링크만 보내면 "납품물이 없다"고
  느끼는 구매자가 있다.
- 리포트 화면의 유료 확장: 표지(브랜드·측정 조건·날짜) · 답변 60개 기반
  신뢰구간 · 경쟁사 점유율 · 엔진별 비교 · 출처 분석 · **개선 가이드
  섹션(guideMd 렌더)** · PREMIUM이면 전후 비교.
- 인쇄 CSS(페이지 나눔·표지)와 리포트 시각 확장은 Fable 담당 — "혹하게"의
  본체다.
- 가이드는 운영자가 쓰지만 출처 분석 데이터(어느 도메인이 인용되는데 우리가
  없는가)가 이미 리포트에 있어 반자동이다.

## 품질 게이트

- **새 업종 골드 라벨**: 초기 크몽 주문(또는 사전 실측)의 실제 답변을
  라벨링해 골드셋에 추가한다. 로컬 업종 답변의 문체(병원 나열·지역 표기)에서
  판정기 정확도를 CI가 지키게 한다. 골드 라벨은 판정기 채점용 정답지다 —
  고객 데이터와 다른 것이지만, 새 업종 답변이 그 재료가 된다.
- 발송 전 `--dry` 의무 유지. 60답변 실행의 소요·원가를 CLI가 찍는다
  (예상 ~10분 · ~2,400원).
- 배송 체크리스트 문서화: 별칭 확인 · `ChatGPT 0%/Gemini 양수` 지문 ·
  출처 뭉침 · 링크 오리진.

## 크몽 상품 문안

초안은 이 단계에서 작성한다(제목 · 3단 패키지 설명 · FAQ · 발주 시 필요한
정보 안내 — 브랜드명·업종·지역·사이트 주소·경쟁사). 등록은 운영자.
"무료 샘플 → DELUXE" 퍼널을 설명문에 반영하고, 랜딩의 질의 프로토콜
카드(무엇을 묻는지 공개)를 신뢰 근거로 링크한다.

## 성공 기준

- 크몽 문의 → 무료 샘플 → DELUXE 납품까지 **실제 1건 리허설** 완료
- PDF가 인쇄해도 어색하지 않다
- 60답변 실행이 실패 없이 완주한다
- 새 업종 최소 1개에서 골드 라벨 게이트 통과
