# 인용 출처 집계 (2026-07-30)

## 왜 넣었나

언급률 0%는 소규모 브랜드에게 알려주는 값이 없다 — 고객이 이미 안다. 직접
ChatGPT에 5번 물어봐도 10분이면 아는 사실이다.

집행 가능한 정보는 **"AI가 이 카테고리 질문에 답하면서 어떤 페이지를 읽는가"**다.
구글 1위는 못 해도, AI가 반복 인용하는 리뷰 정리글에 들어가는 건 할 수 있다.
엔진이 이미 `citations`를 수집하고 있었는데 질의를 넘어 집계하지 않아 배송할
수 없었다.

## 실측으로 드러난 문제 둘

### 1. Gemini는 실제 도메인을 주지 않는다

```
uri  : https://vertexaisearch.cloud.google.com/grounding-api-redirect/AUZIYQHBzeBT…
title: "tistory.com"
```

URI가 리다이렉트 프록시다. URL을 파싱하면 **모든 Gemini 출처가
`vertexaisearch.cloud.google.com` 하나로 뭉개진다.** 실제 도메인은 `title`에만
있다.

`Citation.domain?` 필드를 추가하고 Gemini 어댑터가 `hostnameFromTitle`로 채운다.
엔진별 사정은 어댑터가 알고, 집계 쪽은 엔진마다 다른 예외를 모른다.

`title`이 항상 도메인은 아니다 — ChatGPT는 실제 문서 제목("무신사 - MUSINSA
Corporation")을 준다. 호스트명처럼 생긴 것만 인정한다: 공백·슬래시 없고,
점으로 나뉜 레이블 둘 이상, 마지막 레이블이 글자 TLD.

**효과:** 도메인 11개 → 17개. 실제 한국 출처가 드러났다 — `tistory.com`(2건),
`eomisae.co.kr`, `sallaemallae.com`, `runningwikii.com`, `daum.net`,
`reddit.com`, `youtube.com`.

### 2. 하위 도메인이 남의 사이트로 분류됐다

`corp.musinsa.com`이 인용됐는데 `selfDomains: ['musinsa.com']`과 정확히
일치하지 않아 `third-party`가 됐다. 리포트에 **"AI가 당신 사이트를 한 번도
읽지 않았습니다"**라는 거짓이 적힐 상황이었다.

점 경계 접미사 매칭으로 고쳤다. `endsWith('musinsa.com')`만 쓰면
`fakemusinsa.com`이 우리 것으로 잡히므로 반드시 `.` + 도메인으로 본다.

## 설계 결정

**세는 단위는 답변 수다.** 원시 인용 수가 아니다. 한 답변이 같은 페이지를
5번 인용해도 1로 센다. 원시 인용을 세면 답변이 길수록 출처가 중요해 보이는데,
그건 출처의 영향력이 아니라 답변의 길이다.

**eTLD+1을 계산하지 않는다.** 제대로 하려면 public suffix list가 필요하고,
흔한 대안인 "뒤 두 레이블"은 한국 도메인을 전부 깨뜨린다 — `musinsa.co.kr`이
`co.kr`로 묶여 서로 다른 회사가 한 덩어리가 된다. 호스트명을 그대로 쓴다.
대가는 `hoka.com`과 `nz.hoka.com`이 따로 집계되는 것이고, 그건 리포트를 읽는
사람이 알아볼 수 있는 종류의 분리다. `co.kr` 오집계는 알아볼 수 없다.

**비율은 신뢰구간이다.** 무료 진단은 답변이 3개뿐이라 "3개 중 2개 = 67%"의
구간이 [21%, 94%]다. 점추정만 보여주면 거짓말이 된다 — 다른 모든 지표와 같은 규칙.

**인용 0건인 답변도 분모에 넣어야 한다.** 인용 있는 답변만 넘기면 모든 출처의
비율이 부풀려진다. `aggregateSources`의 호출부가 지켜야 하는 계약이다.

## 실측 출력 (픽스처 4건)

```
답변 4개 중 4개에 인용 · 서로 다른 도메인 17개
우리 사이트(musinsa.com) 인용된 답변: 1개

 2개  50%  15% ~ 85%   tistory.com
 1개  25%   5% ~ 70%   corp.musinsa.com [우리]
 1개  25%   5% ~ 70%   official.zigzag.kr [경쟁사]
 1개  25%   5% ~ 70%   eomisae.co.kr
 …
```

`tistory.com`이 4개 답변 중 2개에 걸렸다. 30질의로 늘리면 반복 출처가 더
분명히 갈린다 — 그게 크몽 리포트의 실행 목록이 된다.
