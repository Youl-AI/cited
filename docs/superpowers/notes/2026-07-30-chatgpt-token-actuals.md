# ChatGPT 엔진 실측 (2026-07-30)

Responses API + `web_search` 툴. 설계 문서가 "확정하지 못했다"고 남긴 항목이다.

## 결론

| 항목 | 값 |
| --- | --- |
| 모델 | `gpt-5-mini` |
| 호출당 원가 | **39~44원** |
| 검색 횟수 | 1~2회 |
| 입력 토큰 | 9,600~14,000 |
| 출력 토큰 | 370~460 |
| 사고 토큰 | 1,660~2,050 |
| 인용 | 5건 |
| 답변 길이 | 1,000~1,100자 |

Gemini(33원, 653~736자, 인용 4~5건)와 같은 급이다. 설계 문서의
"입력 8,000 토큰" 가정은 **대체로 맞았다** (9.6k~14k로 조금 더 크다).

## Gemini와 정반대인 지점 셋 — 같은 공식을 쓰면 원가가 틀린다

### 1. 검색 청구 단위가 **호출**이다 (Gemini는 질의)

응답의 `action.queries`에 질의가 3~4개 들어 있어도 청구 카운터
`tool_usage.web_search.num_requests`는 **1**이었다.

```
action.queries: ["2026 best running shoes…", "…site:nike.com", "…site:asics.com"]
tool_usage.web_search.num_requests: 1
```

질의를 세면 원가가 3~4배로 부풀려진다. 어댑터는 `num_requests`를 읽는다.
(Gemini는 정확히 반대다 — "billed for each search query that the model
decides to execute". 거기서는 호출을 세면 절반으로 과소 계상된다.)

### 2. 사고 토큰이 출력 토큰에 **포함**되어 있다 (Gemini는 별개)

```
total_tokens 8,826 = input 8,468 + output 358,  그중 reasoning 84
```

`pricing.ts`가 `tokensOut + tokensThinking`으로 더하므로, 어댑터에서 빼두지
않으면 사고 토큰이 두 번 청구된다. 실측에서 사고 토큰이 1,664~2,048로
출력 토큰(370~460)보다 **크므로** 이중 계상되면 원가가 5배 틀린다.

### 3. 검색으로 긁어온 본문이 입력 토큰으로 **청구된다** (Gemini는 무료)

검색 없이 4,491 → 검색 켜고 8,468. 차이가 그대로 청구된다.
Gemini는 그라운딩 본문이 입력 토큰에 잡히지 않는다.

## 검색을 강제해야 한다

`tools: [{ type: 'web_search' }]`만 붙이면 **검색이 실행되지 않는다.**
실측에서 `web_search_call`이 아예 없었고 인용도 0건이었다 — 모델이
학습된 지식으로만 답한 것이다.

그 답변을 측정하면 우리가 재는 것이 **작년 학습 데이터**가 된다. GEO는
"지금 검색되는 내용이 답변에 어떻게 반영되는가"인데, 검색을 안 하면
브랜드가 콘텐츠로 영향을 줄 여지가 없다. `tool_choice: 'required'`를 켠다.

## 인라인 인용이 언급률을 부풀린다 — 반드시 제거해야 한다

ChatGPT는 Gemini와 달리 인용을 **본문 안에 마크다운 링크로** 박는다:

```
- Nike Pegasus 42 — 반응성 좋고 다목적. ([nike.com](https://www.nike.com/a/pegasus-42…))
```

1차 매칭은 문자열을 보므로 URL 속 브랜드명을 언급으로 센다. 실증:

| 픽스처 | 브랜드 | 정리 전 | 정리 후 |
| --- | --- | --- | --- |
| 패션 쇼핑몰 | 애플 (`apps.apple.com` 인용) | 언급 O ❌ | 언급 X ✅ |
| 러닝화 | 브룩스 (본문에서 실제 추천) | 언급 O | 언급 O ✅ |

답변이 어떤 브랜드를 **출처로만** 인용해도 언급으로 잡히면 고객의
Cited Rate가 실제보다 높게 나온다. 우리가 파는 것이 그 숫자다.

링크가 본문의 **60%**를 차지한다 (1,108자 → 457자). 제거하면 고객에게
보여줄 증거 원문도 읽을 만해진다. 인용 정보는 `annotations`에서 이미
뽑아 `citations`에 담으므로 잃는 것이 없고, 원본은 `raw`에 남는다.

## 모델 선택 근거

같은 질의 3개(러닝화 · 패션몰 · 중고거래), 검색 강제:

| 모델 | 호출당 | 인용 | 답변 길이 |
| --- | --- | --- | --- |
| gpt-5.4-mini | 22원 | 2건 | 276~821자 |
| **gpt-5-mini** | **44원** | **11건** | **1,030~1,190자** |
| gpt-5 | 89원 | 14건 | 595~1,410자 |
| gpt-5.5 | 110원 | — | — |

`gpt-5.4-mini`가 절반 값이지만 3건 중 2건에서 **인용 0건에 답변 276자**였다.
얄팍한 답변은 브랜드를 덜 언급하므로 **언급률이 체계적으로 낮게 측정된다** —
원가를 아끼려다 측정값 자체를 망가뜨린다.

`gpt-5-mini`가 Gemini와 답변 길이·인용 밀도가 가장 비슷해 엔진 간 비교
가능성이 유지된다. 요금제 영향은 Starter(질의 10 × 샘플 3 × 주 1회) 기준
월 5,676원으로 99,000원 요금제에서 감당된다.

`gpt-5-search-api`는 Responses API를 지원하지 않는다(400).

## 곁가지로 고친 것 — PRICING.gemini가 틀려 있었다

`PRICING.gemini`에 `flash` 단가($1.50 / $9.00)가 들어 있었는데 엔진
(`GEMINI_MODEL`)은 `flash-lite`로 돌고 있었다. 유료 Gemini 원가가 **5배**
부풀려 계산되고 있었다. `flash-lite` 단가($0.30 / $2.50)로 정정했다.

단가표와 엔진 기본 모델은 같이 움직여야 한다.
