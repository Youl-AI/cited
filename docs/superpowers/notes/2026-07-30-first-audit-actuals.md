# 무료 진단 1건 전체 실행 실측 (2026-07-30)

`pnpm audit:new` → `pnpm audit:list` → `pnpm audit:run <id> --dry`
브랜드 무신사 · 카테고리 패션 · 경쟁사 29CM·지그재그 · 도메인 musinsa.com

## 가장 중요한 결과: 별칭 수정이 실제로 통했다

```
엔진별:
  chatgpt     100% (44% ~ 100%)
  gemini       67% (21% ~ 94%)
```

**ChatGPT가 Gemini보다 높다.** 2026-07-30 이전 실측에서는 ChatGPT가 한글
브랜드명을 한 번도 쓰지 않아 언급률이 구조적으로 0%로 나오는 상태였다.
Task 6-2의 별칭 생성(`MUSINSA, 무탠다드, 무신사스탠다드`)이 그 구조적 0%를
없앴다는 것을 처음으로 실제 파이프라인에서 확인했다.

계획서가 "이 패턴이 별칭 문제의 지문"이라고 적어 둔 `ChatGPT 0% / Gemini 양수`
꼴이 **역전됐다.** 이게 이 태스크에서 얻은 가장 값어치 있는 확인이다.

## 숫자

| 항목 | 값 |
| --- | --- |
| 수집 | 6/6 성공 (질의 3 × 엔진 2 × 샘플 1) |
| 수집 원가 | **223.3원** (계획서 예측 250원) |
| 수집 소요 | 33.1초 |
| 전체 소요 | 42초 |
| 판정 | 1차 후보 18건 중 9건 통과 → 2차 배치 1회(9건) · 미판정 0 |
| 언급률 | 83% (44% ~ 97%) — 답변 6개 중 5개 |
| 순위 | 무신사 5회 · 29CM 2회 · 지그재그 2회 |
| 인용 출처 | 6/6 답변에 인용 · 도메인 **20개** |
| 우리 사이트 | 1개 답변에서 인용됨 |

원가는 수집 223.3원 + 별칭 약 2.6원 + 판정 약 2원 ≈ **228원/건**.

## 계획서 체크리스트 확인

- **질의에 브랜드명 없음** — "30대 남자 옷 어디서 사는 게 좋아?",
  "가성비 좋은 온라인 패션 쇼핑몰 추천해줘" — 통과
- **별칭에 MUSINSA 있음** — 통과
- **ChatGPT 0% / Gemini 양수 꼴 아님** — 역전됨, 통과
- **증거 원문이 한국어** — 두 엔진 모두 한국어 산문, 통과
- **언급 판정이 눈으로 맞음** — ChatGPT 답변의 `무신사(스트리트·캐주얼)`,
  `29CM·쿠팡·지마켓`이 각각 제대로 잡혔다. 통과
- **인용 출처가 비어 있지 않음** — 20개 도메인. Gemini 출처가
  `vertexaisearch.cloud.google.com` 하나로 뭉치지 않았다(`Citation.domain`이
  살아 있다). 통과
- **`--domains` 정규화** — `https://www.musinsa.com/kr/main`을 넣었는데
  `musinsa.com`으로 저장됐고, 소유 판정이 실제로 1건 잡혔다. 통과

## 인용 출처가 리포트의 실질이라는 근거

도메인 20개 중 상위:

```
   3개    50% tistory.com
   2개    33% youtube.com
   1개    17% apps.apple.com / daebak.co / dashbooster.com
   1개    17% fuga-studios.com / gq.com / harpersbazaar.co.kr
```

`tistory.com`이 6개 답변 중 3개에 등장한다. 언급률 0%인 고객에게 줄 수 있는
유일하게 집행 가능한 문장이 이것이다 — "AI가 당신 카테고리를 답할 때 절반은
티스토리 글을 읽는다."

## 자동화 판단용 숫자

한 건에 **42초 · 228원**이다. 운영자가 `--dry`로 눈으로 확인하고 발송하는
현재 방식은 건당 2~3분쯤 든다. 하루 10건까지는 수동으로 감당되고,
그보다 늘면 자동 발송으로 넘겨야 한다. 넘어가는 기준은 시간이 아니라
**"손으로 고칠 게 없어진 시점"**이다 — 이번 실행에서는 고칠 것이 없었다.

## 부수적으로 만든 것

`pnpm audit:reject <id> "<사유>"`. 계획서 Produces에는 있는데 Step 8에
스크립트가 없었다. 이 검증으로 만든 행을 대기 목록에서 빼야 했고, 빼지 않으면
`audit:list`가 영원히 "24시간을 넘긴 신청"을 경고한다 — 그 경고가 늘 켜져
있으면 **진짜 늦은 신청을 못 본다.** 행은 지우지 않고 상태만 `rejected`로
바꾼다(인증 게이트 감사와 반복 신청 관측에 행이 필요하다).
