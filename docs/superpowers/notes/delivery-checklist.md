# 크몽 주문 배송 체크리스트

> 2026-07-31 작성 · Task 10 Step 2. 주문 1건을 받아 납품까지 가는 운영 절차.
> CLI 시그니처는 `scripts/audit-*.mts`의 사용법 헤더 기준. 상품 문안은
> `docs/kmong/listing.md`.
>
> 원칙: **돈이 드는 명령(`audit:run`)은 `--dry`까지 눈으로 확인한 뒤에만.**
> 60답변 실행 1회 ≈ 2,400원 — `--dry`도 수집·판정을 실제로 하므로 같은 돈이 든다.
> 표준 플로우(dry 저장 → `audit:publish` 발송)는 측정이 1회라 **건당 ~2,400원**
> (기존 dry+발송 이중 측정 ~4,800원 — 2026-07-31 리허설 발견 #1로 개선).

## 주문 접수

- [ ] 필요한 정보 수신 (브랜드·업종·지역·도메인·경쟁사·서비스 소개) —
      `docs/kmong/listing.md` §4의 발주 요청문을 크몽 메시지로 보낸다.
      ★ 고객 이메일은 받지 않는다. 크몽 주문은 **운영자 이메일**로 등록한다
      (`audit:new`의 --email은 필수라 운영자 주소를 넣는다) — 리포트 메일은
      운영자 보관용이고, 고객 접점은 크몽 메시지 하나로 일원화한다.
      웹 링크를 고객에게 주면 사이트의 요금제·구독 유도에 노출된다 —
      크몽 직거래 유도 정책 위반 소지(계정 제재 리스크). 2026-07-31 결정.
- [ ] 지역형 업종(치과·필라테스 등 15종)인데 지역이 없으면 **등록 전에**
      되묻는다 — CLI가 어차피 거부하지만, 고객 응답 대기가 납기를 갉아먹으므로
      첫 메시지에서 받아내는 것이 맞다.
- [ ] `pnpm audit:new "<브랜드>" "<업종>" --email <운영자 이메일> --tier <standard|deluxe|premium> --region "<지역>" --competitors a,b,c --domains example.com --source kmong`
      - `--source`는 기본값이 `kmong`이라 생략 가능하지만, 명시를 권장한다
        (인증 게이트 감사용). `web`은 쓸 수 없다(폼 전용).
      - `--competitors`는 최대 3개, `--domains`는 고객 사이트(출처 소유 판정용).
        도메인이 없으면 리포트에서 "우리 사이트 인용 여부" 줄이 빠진다 —
        "없음" 확인을 받았는지 체크.
- [ ] (무료 샘플 요청이면 `--tier free`로 등록해 먼저 배송) — 무료는 템플릿
      질의 3개 × 1회라 아래 "질의" 단계가 **없다** (`audit:queries`가 거부한다).
      바로 실행 단계로 간다.
- [ ] `pnpm audit:list`로 등록 확인. 대기 24시간 초과 경고가 뜨기 전에 처리한다.

## 질의 (유료 티어만)

- [ ] `pnpm audit:queries <id> --brief "<서비스 한 줄 소개>"`
      → 템플릿 3 + LLM 후보 7을 `audit-queries.<id>.json`에 쓴다.
- [ ] 파일 검수 — 후보는 초안이지 완성본이 아니다. 기준:
      - 고객 서비스와 맞는가 (기구 필라테스인데 요가 질문이 섞이지 않았는가)
      - 사람 말투인가 (실제 고객이 그렇게 묻겠는가)
      - 의도가 겹치지 않는가 (가격·비교·초보·상황별로 흩어져 있는가)
      - 브랜드명·경쟁사명·`{지역}` 잔여 슬롯은 어차피 동결이 거부하지만,
        검수에서 먼저 잡으면 왕복이 준다.
- [ ] 질문 초안을 크몽 메시지로 고객에게 보내 확인받는다 (수정 1회).
- [ ] `pnpm audit:queries <id> --freeze` — 검증(개수 10·중복·브랜드명·지역) 통과
      후 DB 동결. **동결 후에는 바꾸지 않는다** — PREMIUM 재측정 비교의 근거다.

## 실행

- [ ] `pnpm audit:run <id> --dry` — 측정하고 결과를 **저장**한다 (발송 없음,
      **돈은 든다** ≈2,400원). 결과 화면에서 확인:
      - 별칭이 비어 있지 않은가
      - `ChatGPT 0% / Gemini 양수` 지문이 없는가 (별칭 누락 신호)
      - 출처가 vertexaisearch로 뭉치지 않았는가
      - 미판정 0인가
      - 지문이 이상하면 원인 해결 후 `--dry` 재실행 — 마지막 측정이 저장된다.
        status·sentAt은 안 건드리므로 리포트 페이지는 발송 전까지 404다.
- [ ] (DELUXE+) 가이드 작성 → `pnpm audit:guide <id> guide.md`
      - 리포트의 출처 분석(어느 도메인이 인용되는데 우리가 없는가)을 근거로
        쓴다. 측정에 없는 주장을 가이드에 넣지 않는다.
- [ ] (DELUXE+) **발송 전 리포트 화면에서 가이드 렌더를 눈으로 확인** —
      마크다운 강조가 깨질 수 있다. 알려진 함정: 닫는 `**` 바로 앞이 `%` 같은
      문장부호이고 뒤에 조사가 바로 붙으면(예: `**0%**입니다`) CommonMark
      규칙상 굵게가 닫히지 않고 `**`가 그대로 노출된다. 닫는 `**` 앞이
      문장부호이면서 뒤에 글자가 바로 붙는 배치를 피한다 — 예:
      `**0%**입니다`는 깨진다 → `**언급률은 0%였습니다.**`처럼 문장 끝까지
      강조하거나(닫는 `**` 뒤가 공백·문장 끝이면 안전), 그 문장은 강조를 뺀다.
- [ ] `pnpm audit:publish <id> --base-url https://cited.co.kr` — dry가 저장한
      측정을 **재측정 없이** 발송 (0원). 고객은 위에서 눈으로 확인한 바로 그
      숫자를 받는다.
      - `--base-url` 없이 보내면 localhost 링크 사고(2026-07-30 실제 발생) —
        지금은 코드가 거부하지만, 습관으로 항상 붙인다.
      - 측정이 72시간을 넘었으면 경고가 뜬다 — 납기 여유가 있으면 `--dry`
        재측정을 고려 (경고일 뿐 발송은 막지 않는다).
      - 메일 발송 실패로 끝나면 재측정하지 말 것 —
        `pnpm audit:resend <id> --base-url https://cited.co.kr` (저장된 결과
        재발송, 비용 0원, 숫자 동일).
- 레거시 직행 경로: `pnpm audit:run <id> --base-url https://cited.co.kr` —
  측정+발송을 한 번에 (≈2,400원). **재측정이 필요할 때만** 쓴다 — dry 확인을
  건너뛰므로 표준 플로우가 아니다.

## 납품

- [ ] 프로덕션 리포트 페이지가 열리는지 브라우저로 확인 (sent 상태여야 200).
- [ ] `pnpm audit:pdf <id> --base-url https://cited.co.kr`
      → `cited-<브랜드>-<날짜>-<auditId 뒤 6자>.pdf` 생성.
      - 파일명에 auditId 접미사가 붙으므로 같은 브랜드를 같은 날 여러 건
        뽑아도(예: deluxe·premium 동시 납품) 덮어쓰지 않는다. 브랜드명의
        파일시스템 금지 문자는 `-`로 치환된다.
- [ ] PDF 열어 확인: 표지·페이지 나눔·한글 서체 정상, 머리글·푸터 없음,
      (DELUXE+) 가이드 섹션 렌더 정상.
- [ ] 크몽 메시지: PDF 첨부 + 한 줄 요약. **웹 링크는 보내지 않는다**
      (직거래 유도 리스크 — 위 "주문 접수" 참고).
      - 한 줄 요약은 숫자를 그대로 — "답변 60개 중 언급 N회 — 언급률 N%
        (구간 n~m%)" (예: "언급률 32% (구간 21~44%)"). 리포트의 구간은
        비대칭(Wilson)이라 ±로 쓰지 않는다. 구간이 넓으면 넓다고 쓴다.
        좋게 포장하지 않는다.
- [ ] (PREMIUM) 4주 뒤 리마인더 등록 → 시점이 오면
      `pnpm audit:remeasure <원본id>` — 원본의 동결 질의를 그대로 복제·동결한
      새 진단이 만들어진다. 이후 실행·납품은 위 "실행"·"납품" 절차 그대로
      (질의 단계 없음 — 새 질의를 만들면 비교가 무효다).
      - 전후 비교에서 신뢰구간이 겹치면 리포트가 "측정 오차 범위"라고 표기한다.
        메시지에서도 상승이라고 쓰지 않는다 — 이 정직함이 상품이다.

## 실패·예외 시

- [ ] 실행 실패(failed) → `pnpm audit:list`에 사유가 찍힌다. 원인 해결 후
      재실행. 실패 원인을 모르면 돈을 다시 쓰기 전에 조사부터.
- [ ] 링크·메일 사고 → `audit:resend` (재측정 금지 — 숫자가 달라져
      "아까 받은 것과 다른데요"가 된다).
- [ ] 납기(질문 확정 후 영업일 2일)를 못 지킬 것 같으면 **미리** 크몽
      메시지로 알린다. 납기 초과는 전액 환불 사유다 (`listing.md` FAQ).
