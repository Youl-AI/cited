# 골드 라벨 데이터셋

판정기(`src/lib/judge/claude.ts` + `src/lib/detection/`)를 채점하는 정답지.
회귀 게이트(`tests/golden/regression.test.ts`)가 이 셋으로 **recall ≥ 95% ·
precision ≥ 90%**를 강제하며, 판정 모델·프롬프트·1차 매칭 로직을 바꾸려면
이 게이트를 먼저 통과해야 한다.

최신 실측 (2026-08-20, 라벨 정정 후, `pnpm test:golden`):

| 지표 | 값 |
| --- | --- |
| recall | **99.1%** (FN 1) |
| precision | **100.0%** (FP 0) |
| 혼동 행렬 | TP 107 · FP 0 · FN 1 · TN 140 |
| 판정 원가 | 199원 / 1회 (in 78,019 · out 12,841 토큰, claude-haiku-4-5) |
| 실행 시간 | 96.0초 |

같은 날 첫 실행(recall 98.1% · precision 96.3%)의 오판정 6건을 원문
대조한 결과 5건이 **판정기 오류가 아니라 라벨 오류**였다 — 운영자 확인을
받아 정정했고(아래 [기록](#라벨-오류-발견-기록)), 위 수치는 정정된
정답지 기준이다. 남은 FN 1건은 계열사 경계 케이스(라벨 정책 미정)다.

## 규모와 구성

- **라벨 248건** = 답변 52건 × (답변마다 브랜드 1~5개). 긍정 108 · 부정 140
  (2026-08-20 정정 반영).
- 브랜드 29개, 업종 세트 7개. 엔진: gemini 답변 46건 · chatgpt 6건.
- 첫 수집 2026-07-29 (200건), 확장 2026-07-31 (+48건 —
  [기록](superpowers/notes/2026-07-31-golden-expansion.md)).

| 세트 | 긍정 | 부정 | 왜 이 세트인가 (판정기가 틀릴 만한 곳) |
| --- | --- | --- | --- |
| `fashion` | 15 | 25 | 명백한 한글 브랜드 + 영문 별칭 — 기준선 |
| `running` | 31 | 9 | 영문/한글 표기 혼재, 제품명이 브랜드처럼 쓰임 |
| `resale` | 19 | 21 | 당근·크림 — 일반명사와 완전히 겹침 (동음이의어의 본체) |
| `fintech` | 19 | 21 | 토스 — "토스하다" 동사와 겹침 |
| `beauty` | 13 | 27 | 소규모 브랜드, 언급이 드묾 — **부정 라벨 공급원** |
| `pilates-suwon` | 3 | 15 | 지역 상호 — 희귀 언급 + 표기 흔들림 (지역형 템플릿 검증) |
| `finance` | 8 | 22 | 카카오뱅크/카카오페이 접두어 쌍 + chatgpt 미국 편중 답변 |

세트 정의는 `scripts/label-subjects.mts`에 근거 주석과 함께 있다.

## 수집 방법

`pnpm label:collect` (`scripts/label-collect.mts`) — **실제 엔진 답변만** 쓴다.
합성 데이터로 잰 정확도는 의미가 없다: 검증 대상은 "실제 AI 답변에서
브랜드를 제대로 짚는가"이지 "우리가 만든 문장을 제대로 읽는가"가 아니다.

- 질의는 손으로 쓰지 않고 제품과 같은 생성기(`generateAuditQueries`)에서
  뽑는다 — 제품이 실제로 던지는 질의 그대로여야 한다.
- 질의에 브랜드명을 넣지 않는다. 넣으면 "물어봤으니 나온다"가 되어 실제
  언급률과 다른 것을 재게 된다 (무료 진단 질의 생성과 같은 규칙).
- 한 답변에 브랜드 여러 개를 물어 라벨을 뽑는다 (답변 40개 → 라벨 200건).
  원가·라벨링 시간이 1/5이고, 제품의 실제 동작(자사 1 + 경쟁사 N 동시
  판정)에 더 가깝다.
- 지역 세트의 브랜드는 **답변이 실제로 언급한 실존 업체**에서 골랐다
  (웹에서 실존 확인). 실존을 못 굳힌 상호('필라테스 루틴')는 뺐다.
- 확장분 수집 원가 실측: 답변 12건 471원 (재수집 1건 포함).

## 라벨링 절차

`pnpm label` (`scripts/label.mts`) — 답변 전문을 보여주고 "실제로 언급된
브랜드 번호"를 입력받는 CLI. 운영자 수작업.

절차가 지키는 두 가지:

1. **1차 매칭 결과를 라벨러에게 보여주지 않는다.** 채점받을 쪽의 답을 먼저
   보면 사람이 거기에 끌린다(anchoring). 그러면 게이트 통과가 "우리가 우리
   답에 동의했다"는 뜻이 된다.
2. **LLM으로 라벨을 채우지 않는다.** 판정기가 Claude인데 정답지도 Claude가
   만들면 자기 자신을 자기 자신으로 검증하게 된다.

- 라벨러: 운영자 1인. 교차 라벨링(2인 이상 일치도 측정): **없음**.
- 라벨링 소요 시간: 미기록.

## 라벨링 기준

- **언급 여부(`label`)** — "매칭된 문자열이 진짜 그 브랜드를 가리키는가."
  동음이의어(일반명사·다른 회사·지명)는 미언급. 판정기의 isBrandReference와
  같은 정의다. CLI가 받는 것은 이 y/n 하나다.
- **position** — **미라벨.** 248건 전부 `labelPosition: null`이다. 라벨링
  CLI가 순서 입력을 받지 않았고, 게이트도 position을 채점하지 않는다.
  position 출력의 검증은 프롬프트 실측(문자 오프셋 사건 —
  `judge/claude.ts` 주석)과 코드 정합성 보정(미언급이면 null 강제)뿐이다.
  순서 정확도의 정량 검증: 미기록.
- **sentiment** — **미라벨·미채점.** 골드셋에 감성 라벨이 없다. 게이트는
  언급 여부만 잰다. sentiment 정확도: 미기록.

## 애매한 케이스 처리

- **동음이의어** — 세트 설계로 정면 배치했다(resale의 당근·크림, fintech의
  토스). 브랜드 프로필의 `ambiguous: true` 플래그(당근·크림·토스 3개)는
  1차 매칭이 자체 통과시키지 않고 **2차 LLM 판정을 강제**하게 만든다.
  라벨은 문맥 기준: 중고거래 앱 "당근"은 언급, 채소 당근은 미언급.
- **부분 언급·희귀 언급** — beauty(소규모 브랜드)·pilates-suwon(동네 상호,
  브랜드당 6답변 중 1곳 등장)이 이 케이스의 부정 라벨을 공급한다.
- **경쟁사 문맥** — 별도 라벨 규칙 없음. 한 답변에 자사·경쟁사가 같이 나와도
  라벨 단위가 (답변 × 브랜드)라서 각 브랜드가 독립적으로 언급/미언급이다.
- **계열사·유사명 경계** — **정책 미기록.** 이번 실측(2026-08-20)에서
  드러난 실례: "신한은행" 라벨러는 답변 속 "신한저축은행 참신한파킹통장"을
  언급으로 라벨했고, 판정기는 별개 법인으로 보아 미언급 판정(FN 처리됨).
  어느 쪽을 정답으로 할지 라벨 정책이 없다 — 운영자 결정 필요.
- **라벨 메모** — CLI가 답변 단위 메모를 받는다. 현재 10건(2종): chatgpt
  금융 답변의 미국 서비스 편중 관찰("국내 서비스라서 해외 앱은 의미가
  없음" 등). 원인은 API `web_search`에 locale 신호가 없어서다 —
  제품 시사점까지 [확장 기록](superpowers/notes/2026-07-31-golden-expansion.md)에 있다.

## 라벨 오류 발견 기록

- **수집 단계 (2026-07-31)** — chatgpt 응답 1건이 `(잠깐 정보를
  확인합니다...)` 17자 스텁. 후보에서 폐기하고 재수집(24원). 스텁 5라벨은
  판정기 검증에 정보가 없다.
- **게이트 실행 중 발견 (2026-08-20, 이 문서 작성 시)** — FP 4건을 원문
  대조한 결과 **네 건 모두 답변 본문에 브랜드가 명시적으로 언급되어 있다.**
  판정기가 맞고 정답지가 틀린 케이스다:

  | 라벨 id | 본문 근거 |
  | --- | --- |
  | `beauty:gemini:가성비 좋은 국산 화장품 브랜드 알려줘::이니스프리` | "1. **이니스프리 (Innisfree)**" — 목록 1번 |
  | `pilates-suwon:gemini:수원 요가원 괜찮은 데 알려줘::리본요가` | "**리본요가 수원점** (팔달구 덕영대로…)" |
  | `finance:gemini:수수료 낮은 송금 방법 알려줘::카카오페이` | "**카카오뱅크 / 카카오페이** : 건당 5,000원 안팎…" |
  | `pilates-suwon:chatgpt:수원 필라테스 어디가 좋아?::더센터오브필라테스` | "더센터오브 필라테스 수원점 — 가성비 좋고…" |

  추정 원인: 번호 입력 방식(답변당 언급 브랜드 번호 나열)에서 누락.
- **FN 2건 중 1건**(`fintech:gemini:신용점수 올리는 방법 알려줘::카카오뱅크`)도
  라벨 오류였다 — canonical("카카오뱅크")과 별칭("카뱅", "kakaobank") 어느
  것도 본문에 등장하지 않는데 라벨이 언급이었다(카카오페이와 혼동 추정).
  나머지 1건(신한은행)은 위 계열사 경계 케이스로, 정책 확정 전까지 유지.
- **정정 반영 (2026-08-20)** — 위 5건(4건 미언급→언급, 1건 언급→미언급)을
  운영자가 원문 확인 후 확정, `candidates.json` 정정 → `labels.json`
  재내보내기 → 게이트 재실행. 결과 recall 98.1%→**99.1%** · precision
  96.3%→**100.0%**. 판정기 오판을 찾으려던 게이트가 역으로 정답지 오류를
  잡아낸 사례다 — 오판정 목록에 원문 발췌를 같이 출력하게 만든 것
  (`regression.test.ts`의 mistakes 출력)이 발견 경로였다.

## 재현

```bash
pnpm label:collect          # 후보 수집 (실제 엔진 호출 — 돈이 든다)
pnpm label                  # 수작업 라벨링 CLI
pnpm label --stats          # 진행 상황
pnpm test:golden            # 회귀 게이트 (실제 판정 API — 1회 ~200원)
```

게이트는 라벨 파일이 없거나 API 키가 없으면 스킵이 아니라 **실패**한다.
게이트가 꺼진 채 초록불이 뜨는 것이 게이트가 없는 것보다 나쁘다.
